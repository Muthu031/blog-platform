# Tasks — Liskov Substitution Principle (LSP)

Easy
- Replace a concrete implementation with a subclass in tests to show substitutability.

Medium
- Fix a hierarchy where a subclass violates LSP (e.g., changes expected method behavior).

Hard
- Design a type-safe strategy set that guarantees LSP across multiple implementations.

Hints
- Ensure method contracts (inputs/outputs/exceptions) remain consistent.
